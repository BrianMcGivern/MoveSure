The taps land now. But the V5 run exposed the next problem: the two checkers disagreed with each other in 8 cases, mostly on G4, reading the same evidence and reaching different verdicts. Three cases had workflow breaks underneath: GC-20's fresh tap after a dispute never landed, GC-19's baseline never went fully terminal, and GC-13's freeze couldn't be tested live.
Change: I added five sentences to both prompts — the worker's and the auditor's. First, classify every artifact by which gate it belongs to before judging it. Second, G4 has one result: a readable matching rules document is CHECKS COMPLETE, and only the tenant's own tap completes it. Third, a fully matching receipt is terminal, so G3 never waits for a second step. Fourth, a captured confirmation counts only when the sender, the window, and every exception condition all hold. Fifth, a hold stays in its own gate. I also made the export print both readers' verdicts per gate, so a disagreement is visible, and made the GC-20 replay create the fresh booking draft when none exists.
After: I re-ran all 20 cases on V8 with live AI and got 20 Pass, 0 Needs work, 0 Fail, still zero false approvals.
